# BTC 청산 흐름 전략 v1.0 — 사전등록 명세
작성일: 2026-07-03 · 상태: 검증 전 (데이터 접촉 전 고정)

이 문서는 데이터를 보기 전에 가설·규칙·기각 조건을 고정하는 사전등록 문서다.
검증 시작 후 이 문서의 진입/청산 조건을 수정하면 해당 검증은 무효이며, 수정본은 v1.1로 새로 등록한다.

---

## 0. 공통 구조 논거

두 셋업 모두 같은 비효율을 수확한다: **강제 흐름(forced flow)**.

- **상대방**: 청산 엔진에 의해 가격 불문 시장가로 포지션이 정리되는 레버리지 트레이더. 이들은 "팔고 싶어서"가 아니라 "팔아야 해서" 판다. 가격에 둔감한 주문 흐름 = 일시적 가격 왜곡.
- **지속 이유**: 레버리지 수요는 구조적으로 소멸하지 않는다(펀딩비 역사가 증거). 청산 메커니즘은 거래소 규칙으로 기계적·공개적·반복적이다. 모두가 알지만, 캐스케이드 한복판에서 반대편에 서는 것은 심리적·기관적 제약(떨어지는 칼, 커리어 리스크) 때문에 실행자가 적다.
- **개인의 수확 가능성**: 보유 시간 수분~수시간, 목표 30~150bps로 왕복 비용 8~12bps의 3배 이상. 밀리초 경쟁 아님. 용량 제약 없음(개인 규모). → 비용·인프라 필터 통과.

## 1. Setup A — 청산 캐스케이드 소진 롱 (Cascade Exhaustion Long)

### 가설
하방 청산 캐스케이드가 소진되면, 강제 매도로 발생한 가격 이탈분의 상당 부분이 단시간 내 회복된다. 이유: 캐스케이드 저점의 매도는 정보가 아니라 마진콜이었으므로, 강제 흐름이 멈추는 순간 그 가격은 펀더멘털 대비 과매도 상태다.

### 트리거 (전 조건 충족 시에만 후보)
- T1. **캐스케이드 감지**: `forceOrder` 스트림에서 60초 내 매도 청산 금액 합계 ≥ 최근 24h 시간당 평균의 8배, 그리고 최소 3건 이상 연쇄
- T2. **가격 이탈**: 캐스케이드 시작 대비 하락 ≥ 0.8% (80bps)
- T3. **소진 확인** (진입 게이트, 셋 다 필요):
  - 마지막 매도 청산 후 90초 경과, 신규 청산 없음
  - 1분 CVD가 음(-)에서 0 이상으로 전환
  - 가격이 캐스케이드 최저점 대비 +0.15% 이상 반등 유지 30초
- T4. **차단 조건**: 캐스케이드가 거시 뉴스 시간대(FOMC/CPI 발표 ±30분)와 겹치면 진입 금지 — 그건 강제 흐름이 아니라 정보 흐름

### 실행
- 진입: T3 충족 즉시 시장가 롱, 1트랜치
- 손절: 캐스케이드 최저점 − 0.15% (최저점 재이탈 = 소진 판단 오류)
- 목표: TP1 = 이탈분의 38% 되돌림 (50% 청산), TP2 = 61.8% 되돌림 (잔량)
- 시간 청산: 진입 후 90분 내 TP1 미도달 시 전량 시장가 청산
- 재진입: 손절 후 동일 캐스케이드에 재진입 1회 허용 (T3 재충족 시)

### 사전 예측 (기각 가능해야 함)
- 예상 승률 45~60%, 평균 손익비 ≥ 1.5R, 비용 후 기대값 ≥ +15bps/건
- 발생 빈도: 주 3~10회 (변동성 레짐 의존)

### 기각 조건 (하나라도 충족 시 v1.0 폐기)
- 30건 도달 시 비용 후 평균 ≤ 0bps
- 50건 도달 시 비용 후 평균 < +8bps 또는 승률 < 35%
- 최대 연속 손실 10회 초과

## 2. Setup B — 트랩드롱 플러시 숏 (Trapped-Long Flush Short)

### 가설
박스 상단 돌파가 신규 롱(OI 증가)을 유입시킨 뒤 실패하면, 물린 롱들의 손절·청산이 하방 연료가 된다. 가격은 단순 박스 중앙이 아니라 **그 롱들의 청산 밀집 구간까지** 자석처럼 끌린다.

### 트리거
- T1. **미끼 국면**: 박스 상단(4h 기준 레인지) 돌파 시도 + 돌파 구간에서 OI 증가 ≥ +1.5% (5분 폴링 기준) — "신규 롱 유입" 확인. *OI 증가 없으면 숏커버 랠리로 별도 분류, 본 셋업 아님*
- T2. **트랩 확정**: 돌파 후 가격이 박스 상단 아래로 복귀 + 15분 내 상단 재탈환 실패
- T3. **연료 확인**: 돌파 구간 유입 OI가 아직 청산되지 않음 (OI가 돌파 전 수준으로 회귀하지 않았을 것 — 회귀했다면 이미 탈출, 연료 없음)

### 실행
- 진입: 2트랜치 — ① 상단 복귀 확인 시 50%, ② 상단 리테스트 실패 시 50% (리테스트 없이 하락 시 ①만 운용)
- 손절: 돌파 고점(sweep high) + 0.1%
- 목표: TP1 = 박스 중앙 (50% 청산), TP2 = 추정 청산 클러스터 — 돌파 구간 평균가 기준 10x 레버리지 청산가(약 −9%)와 25x(약 −3.8%) 중 가까운 쪽. 청산 히트맵 데이터 확보 시 대체
- 시간 청산: 진입 후 8시간 내 TP1 미도달 시 전량 청산
- 무효화: 진입 전 OI가 급감하면 (트랩 롱 자발 탈출) 셋업 취소

### 사전 예측
- 예상 승률 40~55%, 평균 손익비 ≥ 1.8R (기존 프레임워크의 1.85R 기준선 계승)
- 발생 빈도: 주 1~4회

### 기각 조건
- 20건 도달 시 비용 후 평균 ≤ 0bps
- 40건 도달 시 승률 < 30% 또는 평균 R < 1.2

## 3. 두 셋업의 관계

같은 사건의 양면이다. Setup B의 목표 지점(청산 클러스터 타격)이 Setup A의 트리거(캐스케이드 발생)를 만든다. 따라서 B 포지션 보유 중 A 트리거가 발생하면: B의 TP2를 청산 소진 시점으로 동적 전환하고, A 롱 진입은 B 청산 완료 후에만 허용 (양방향 동시 보유 금지).

## 4. 필요 데이터 및 수집

| 데이터 | 소스 | 용도 |
|---|---|---|
| 강제 청산 | `wss://fstream.binance.com/ws/btcusdt@forceOrder` | A-T1, A-T3 |
| OI | `fapi/v1/openInterest` 5분 폴링 (로컬) | B-T1, B-T3 |
| aggTrade/CVD | fstream websocket | A-T3 소진 확인 |
| 가격/레인지 | 기존 파이프라인 | 공통 |
| 청산 히트맵 | Coinglass 등 (선택) | B TP2 정밀화 |

주의: forceOrder 스트림은 1000ms당 대표 1건만 전송한다(전수 아님). 금액 임계값은 이를 감안한 하한 추정치로 캘리브레이션 필요 — 단, 캘리브레이션은 트리거 임계값 조정만 허용하고 진입/청산 구조 변경은 불허.

## 5. 검증 절차

1. **섀도 단계**: 라이브 스트림에서 시그널만 기록, 가상 체결 (랩 v3). 최소 A 30건 / B 20건
2. **판정**: 기각 조건 미충족 + 사전 예측 범위 내 → 소액 라이브 ($100~300, 1x 격리)
3. **라이브 단계**: 20건 후 섀도와 라이브의 슬리피지 괴리 측정 → 비용 가정 갱신
4. 어느 단계에서든 기각 조건 충족 시: 폐기하고 부검 문서 작성 (무엇이 틀렸는지 명시) 후 v1.1 재등록
